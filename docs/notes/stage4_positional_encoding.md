1) why wouldn't simply adding the raw position number (0, 1, 2, 3, 4...) directly to each token's embedding work well?
token embeddings are learned values, typically initialized and trained to stay in a small, consistent range (roughly -1 to 1) because that's the range where gradients flow well and the network's internal computations (dot products, layernorm, etc.) behave predictably. If you add a raw position number like 500 to an embedding whose values are around 0.3, you get something like 500.3 — the position signal completely dominates and drowns out the actual content signal (what the token means). The embedding essentially stops encoding "meaning" and just encodes "which position am I," which defeats the purpose. Worse, this also breaks generalization — a model trained on sequences up to length 512 has literally never seen a "position 600" value if you test on a longer sequence, so it has no idea how to handle it.
(Okay there would be a problem if we just add raw positional numbers directly to each token's embedding work. As there is no upper limit means the numbering can go up to a very large limit and transformer architecture is itself a neural network architecture and neural networks work on back propogation and back propogation hates big numbers , it works best for numbers between -1 and 1 . So , this is would bring instability)

The sinusoidal solution (the classic "Attention is All You Need" approach): instead of one raw number per position, each position gets a vector of values computed using sine and cosine waves of different frequencies:
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
Every value produced is always between -1 and 1 (since sin/cos are bounded), solving the magnitude problem directly. Different dimensions use different frequencies — some oscillate fast (distinguishing nearby positions), some oscillate slowly (distinguishing far-apart positions) — so the combination across all dimensions gives every position a unique, bounded "fingerprint" vector, which gets added directly to the token embedding.

2) Learned vs. fixed sinusoidal — what's the practical tradeoff, especially regarding sequences longer than anything seen in training?
While learned embeddings can optimize tightly for specific sequence structure with your training data , fixed sinusoidal embeddings rely on mathematical extrapolation to handle context shifts
Learned Embeddings (Hard Failure): The model cannot extrapolate. If you train on a maximum length of 512, the embedding lookup table simply does not have vectors for positions 513 and beyond. Extending the model requires adding new, untrained vectors or using complex interpolation heuristics, both of which severely degrade performance.
Fixed Sinusoidal Embeddings (Soft Failure / Graceful Degradation): The mathematical function (\[sin\] and \[cos\] at varying frequencies) can generate unique positional vectors for any length out to infinity (\(513, 1000, 10000\), etc.). However, because the model's attention weights have never encountered these specific high-position vectors during training, the network's performance still degrades—but it degrades gracefully rather than crashing completely. 

3) Why does addition work for combining position + token embedding, instead of needing concatenation?
We add instead of concatenating because on concatenating the dimension will everytime increase by twice which on adding will preserve the original dimension (addition works because Q/K/V are computed via linear projections, and linearity lets the model mathematically separate content and position signals from the summed vector — while also keeping dimensions consistent throughout the network instead of growing them purely to accommodate position.)
